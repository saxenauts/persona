## Executive Summary

The current Memeplex is a flat topic list (`List[str]`) generated by an LLM reading recent memories. Eval evidence shows it provides minimal measurable benefit (Cohen's d=0.237, not significant). The founder's vision — and the project's own neuroscience research — describe something fundamentally different: a hippocampal index with attractor dynamics, preference direction, temporal evolution, and graph-derived structure.

Three converging problems explain the gap between vision and current state:
1. **Memeplex stores topic labels, not preference direction** — "pottery" without "dropped due to pressure"
2. **Link model exists but is invisible during retrieval** — LED_TO/CAUSED_BY edges exist in Neo4j but recall() is pure vector search
3. **Agent tool budget locked at 1** — expand_neighbors() and follow_relationship() are never called (111/111 eval entries = 1 tool call, 2 turns)

The proposed fix: redefine the Memeplex from "flat topic list" to "computed attractor index with evidence pointers," raise the tool budget so links actually get traversed, and add a bounded settle primitive that uses the graph structure already in place.

## 1. Current Architecture (As-Is)

### 1.1 Memeplex Model (`persona/models/memory.py:440-556`)

```python
class Memeplex:
    topics: List[str]           # max 15, e.g., ["fitness", "AI research"]
    people: List[str]           # max 20, e.g., ["Sarah (wife)"]
    projects: List[str]         # max 15
    places: List[str]           # max 10
    concepts: List[str]         # max 10
    last_week_topics: List[str]
    last_month_topics: List[str]
    recent_focus: str           # 1-2 sentences
    memory_stats: MemoryStats
    timeline_summary: str
```

Generated by: `refresh_memeplex()` in `persona/services/consolidation_service.py:464-559`
Input: Last 30 episodes + 50 entities, fed to LLM with `MEMEPLEX_REFRESH_PROMPT`
Output: JSON blob stored as single Neo4j node
Injection: `{world_model}` slot in system prompt at evidence_hierarchy RANK 3 (lowest)

### 1.2 Link Model (`persona/models/memory.py:270-287`)

```python
class MemoryLink:
    source_id: UUID
    target_id: UUID
    relation: str       # "MENTIONS", "LED_TO", "CAUSED_BY", "RELATES_TO", "CONTRADICTS", "NEXT", "PREVIOUS"
    properties: Dict    # confidence, evidence, timestamp
```

**Creation paths**:
- **During ingestion** (immediate): MENTIONS (Episode → Entity), NEXT/PREVIOUS (temporal chain)
- **During integration** (async, post-session): LED_TO, CAUSED_BY, RELATES_TO, CONTRADICTS — created by LLM-powered integration agent (`persona/services/integration_agent.py:55-151`)

**Retrieval tools** (exist but rarely called):
- `expand_neighbors(memory_id)` — all connected memories
- `follow_relationship(source_id, relation_type)` — specific chain traversal

### 1.3 The Retrieval Gap

In the 100Q eval (119 entries):
- 111/111 entries: exactly 1 tool call (`recall()`), 2 turns
- 0/111 entries use `expand_neighbors()` or `follow_relationship()`
- System prompt says: "One good recall often gives you everything you need"
- Result: The entire graph structure — all causal links, contradictions, temporal chains — is bypassed

## 3. External Research Findings

### 3.1 Hippocampal Indexing Theory

**Teyler & DiScenna (1986), Teyler & Rudy (2007)**:
The hippocampus is an INDEX, not a storage mechanism. It maintains pointers to distributed neocortical patterns. A partial cue activates the hippocampal index → reactivates the full pattern. This is content-addressable O(1) retrieval, not O(N) scanning.

**Mapping to Persona**: The memeplex should store POINTERS to actual memory IDs (seed_ids), not topic labels. A partial cue ("cooking") should activate the full attractor basin — the person's relationship with cooking, what they tried, what they dropped, what they kept.

### 3.2 Complementary Learning Systems (McClelland et al. 1995)

Two systems with complementary properties:
- **Hippocampus** (fast learner): Stores specific episodes with pattern separation → Persona's memory store
- **Neocortex** (slow extractor): Extracts statistical regularities → LLM weights
- **Replay**: Hippocampal patterns replayed during sleep, gradually training neocortex → Consolidation/integration pipeline

**Mapping to Persona**: The integration agent IS the replay mechanism. But replay only runs on session close and its outputs (links) are invisible at query time. The consolidation pipeline needs to feed BACK into the retrieval path.

### 3.3 Memeplex Theory (Dawkins/Blackmore)

A memeplex is a group of co-replicating memes — beliefs, habits, preferences that REINFORCE each other. Identity isn't a list of traits; it's a self-reinforcing NETWORK with:
- **Co-replication**: Memes that travel together reinforce each other's survival
- **Conflict**: When memes collide → cognitive dissonance → narrative reinterpretation
- **Evolution**: Memeplexes shed, acquire, and reorganize memes based on experience

**Mapping to Persona**: "pottery" and "cooking" are NOT equivalent entries in a topic list. One is a dead meme (dropped, pressure/deadlines), one is a living meme (active, social element). The memeplex should encode meme LIFECYCLE STATUS, not just existence.

### 3.4 Narrative Identity (McAdams, Ricoeur)

Identity is an internalized, evolving STORY — integrating reconstructed past, perceived present, imagined future. Provides unity ("same person across years of change"), moral purpose (themes/commitments), temporal coherence (beginning → middle → end).

**Mapping to Persona**: The 4-pillar model maps directly:
- Episode → what happened (chronological evidence)
- Psyche → who am I (themes + traits that evolve)
- Entity → characters in the story (people, places, concepts)
- Note → imagined future (goals, tasks, intentions)

### 3.5 Frontier Lab Trajectory

- **PersistBench (Feb 2026)**: 53% cross-domain leakage, 97% memory-induced sycophancy — shows raw memory injection is dangerous without domain tagging and conflict detection
- **Google Titans/MIRAS**: Updatable core memory during inference — memory as first-class compute resource
- **Anthropic**: Adding Knowledge Base feature for persistent memory
- **OpenAI**: Memory already key differentiator for ChatGPT

**Implication**: Even with perfect reasoning, future LLMs still need: identity persistence, autobiographical evidence with provenance, trajectory tracking (contradictions/transitions), grounding that overrides model priors. The memeplex survives model upgrades ONLY if it provides STRUCTURE (pointers, weights, trajectories) not LABELS (topic lists that smarter models won't need).

## 4. Oracle's Architectural Recommendation

### 4.1 Memeplex v2: AttractorCards

Redefine each entry in the memeplex from a flat string to a structured attractor basin:

```python
class AttractorCard:
    name: str                       # "cooking"
    aliases: List[str]              # ["culinary arts", "food prep"]
    seed_ids: List[UUID]            # Pointers to actual Episode/Psyche/Entity/Note IDs
    preference_direction: str       # "active, enjoys social/cultural element"
    valence: str                    # "approach" | "avoid" | "ambivalent"
    time_profile: str               # "enduring" | "recent" | "dropped" | "revisited"
    open_tensions: List[str]        # ["likes cooking but dropped formal classes"]
    active_flag: bool               # Currently part of identity or archival
    next_hops: List[str]            # Preferred edge types for navigation from this basin
```

vs current: `topics: ["cooking"]`

The difference: "cooking" tells the LLM nothing beyond the question text. "cooking: active, approach, social/cultural emphasis, dropped formal classes, try casual settings" tells the LLM which MCQ option to pick — and more importantly, provides REAL-WORLD discriminative value for any query about this user's relationship with cooking.

### 4.2 settle() Tool Primitive (Phase 0 from Neuroscience Paper)

New tool the LLM can call:

```python
async def settle(query: str, limit: int = 10, hops: int = 1,
                 edge_types: List[str] = ["LED_TO", "CAUSED_BY", "RELATES_TO", 
                                          "CONTRADICTS", "MENTIONS", "NEXT"]):
    """
    1. recall(query) → candidate nodes
    2. expand_neighbors() on top candidates → induced subgraph
    3. Score by: similarity + recency + edge_support + active_flag + contradiction_coverage
    4. Return coherent memory set (mutually-supportive subgraph, not just top-K)
    """
```

This is NOT a router — it's a tool the LLM chooses to call when it needs deeper context. It uses the graph structure that already exists.

### 4.3 Raise Tool Budget

Change system prompt from:
```
"One good recall often gives you everything you need."
```
To:
```
"recall → settle/expand → answer. Use 2-3 tool calls for questions requiring preference discrimination or temporal reasoning."
```

### 4.4 Graph-Derived Memeplex Generation

Instead of:
```
LLM reads 30 episodes + 50 entities → outputs topic labels
```
Do:
```
1. Compute attractor membership from link density + interaction stats + recency
2. Group memories into attractor basins by connection strength
3. Use LLM only to: summarize each attractor, extract preference direction from Psyche/Episode evidence
4. Store seed_ids (actual pointers), not just labels
```

### 4.5 Replay as Post-Answer Writeback

After answering a query:
- Store which nodes/edges were traversed
- Increment weights (salience, edge strength)
- Update active_flag (recently-used basins stay "hot")
- The attractor landscape self-maintains across sessions and model upgrades

## 5. Implementation Priority

### Tier 1: Immediate (< 4 hours, biggest lift)

**Raise tool budget + force multi-step retrieval**. Change system prompt to encourage recall → expand_neighbors → answer. This alone would let the agent use links that ALREADY EXIST without any new code.

**Evidence**: In the eval, failures are predominantly RETRIEVAL_INSUFFICIENT (not that evidence doesn't exist — it does — but it's not retrieved). The links between memories contain the discriminative signal. The agent just never follows them.

### Tier 2: Near-term (1-2 days)

**Add settle() tool + Memeplex v2 schema**. Implement bounded settling as a tool primitive. Redefine Memeplex fields to include preference_direction, valence, time_profile, seed_ids. Update `refresh_memeplex()` to compute from graph structure.

### Tier 3: Medium-term (1-2 weeks)

**Graph-derived memeplex generation + replay writeback**. Full implementation of attractor membership computation, post-answer weight updates, active_flag decay. This is Phase 0 + Phase 1 from the neuroscience paper.

### Tier 4: Long-term (Phase 2-3 from neuroscience paper)

**Navigation engine (Successor Representation) + memetic variants (concept sense evolution)**. These require significant new infrastructure but are the full realization of the hippocampal index vision.

## 6. Why This Survives 10+ Model Upgrades

| LLM Capability | What Persona Still Provides |
|---------------|---------------------------|
| Perfect reasoning | Identity persistence as time-indexed, contradiction-tolerant state |
| Infinite context | Autobiographical evidence with provenance (not just "known facts") |
| Built-in memory | Durable activation landscape (attractors + weights + transitions) |
| Self-updating | Controllable navigation/replay — system updates itself from lived experience |

Flat topic lists won't survive because smarter models won't need them — they can infer "this user likes cooking" from a single recall. An attractor index that POINTS TO EVIDENCE and UPDATES VIA REPLAY survives because it provides what no model can derive from scratch: the user's STORY as it evolved through time, with all its contradictions, transitions, and living/dead memes intact.
